# Видеоаналитика салона «Никольская»

Каждый вечер — таблица «мастер → его клиенты за день»: фото, время визита,
кресла, уверенность. Всё локально на Mac mini M4, 8 камер Hikvision DS-H208QA.
Спецификация — ТЗ от 06.10.2026.

## Что уже есть

Ядро правил, которое считается без видео и покрыто тестами (`pytest`, 67 тестов):

| Раздел ТЗ | Модуль | Что делает |
|---|---|---|
| 2. Реестр кресел | `chairs.py`, `config/salon.yaml` | слияние вида кресла с двух камер в одно физическое кресло; привязка сдвинутых кресел на колёсах |
| 2. Калибровка | `geometry.py` | гомография по 4+ точкам, полигоны, кольцо 0.4–1.2 м |
| 4.1 / 4.5 Метка на человеке | `tracking/global_ids.py` | венгерский алгоритм по каждой камере, новые ID только на входе, потерянные/слепые зоны, обмен ID назад после пересечения, ИК-режим |
| 4.2 Посадка | `sittings.py`, `pose.py` | ≥ 5 мин (барбер 3), мастер в кольце ≥ 2 мин, склейка разрывов ≤ 3 мин, отдых мастера ≠ посадка, мастер стрижёт мастера |
| 4.3 Визит | `visits.py` | присутствие → куски → склейка по лицу/одежде (< 30 мин, после выхода — ≤ 20 мин), мойка внутри визита, предел 9 ч |
| 5. Мастер | `attribution.py`, `staff.py` | голосование временем рук, второй мастер (≥ 20 % или мойка), смена из CRM, закреплённое кресло, запись; приход/уход/выходы/загрузка |
| 5.2 Самопроверка | `checks.py` | 7 ночных правил, включая сверку с чеками CRM ± 1 |
| 6. Фото | `photos.py` | лучший кадр (вход > зеркало > потолок), 3 запасных, «лица нет», повторный / возможно повторный, 90 дней |
| 8. Отчёт | `report.py`, `storage.py` | CSV, шапка дня, сводка по мастерам, очередь проверки, Telegram, SQLite, SQL только на чтение для бота |
| 7. Конвейер | `pipeline/rtsp.py`, `pipeline/live.py`, `pipeline/llm.py`, `deploy/*.plist` | RTSP с переподключением, «камера молчит > 2 мин», Ollama (VLM/SQL), launchd |

**Распознавание подключено** (`pipeline/detector.py`, `pipeline/faces.py`, `roles.py`) — из
готовых открытых проектов, без самописной детекции:

| Задача | Чем |
|---|---|
| люди и скелеты | Ultralytics YOLO11-pose (на Mac — Apple GPU `mps` или CoreML) |
| сдвинутые кресла | Ultralytics YOLO11, класс COCO «chair» |
| ID и одежда | BoxMOT: BoT-SORT + ReID OSNet |
| лица | OpenCV Zoo: YuNet + SFace (Apache-2.0, можно в коммерции) |
| мастер или клиент | сверка лица с зарегистрированными мастерами + «долго в салоне, но не опознан» → «сотрудник?» (подходы систем исключения персонала в рознице) |

Лицо привязывается к человеку строго один к одному (`match_faces_to_people`), отражения
в зеркалах в людей не превращаются (маски). Цепочка проверена на тестовых записях, **на
камерах салона ещё не проверялась**. Ещё не сделано: сайт, бот с вопросами, ночной
разбор спорных визитов по архиву.

**Перенос на Mac mini — пошагово в [MACMINI.md](MACMINI.md).**

## Главный экран: мастер → клиенты

`out/masters.html` (создаётся вместе с отчётом): у каждого мастера фото с камеры,
крупно число клиентов за день и фото каждого клиента со временем прихода.
Файл самодостаточный — картинки внутри, можно переслать одним файлом.

Как фото мастера и клиента не путаются:

- фото мастера берётся только из кадров его собственного ID, фото клиента — только
  из кадров ID клиента;
- каждый кадр сверяется по лицу: если он похож на лицо мастера (для клиента), на
  соседнего клиента или на клиента (для мастера) сильнее, чем на своё, он
  выбрасывается — даже если это самый резкий кадр дня;
- галерея лица клиента чистится от лиц сотрудников перед сверкой;
- один и тот же кадр не может стоять и у мастера, и у клиента;
- если чистого кадра нет — «нет фото» и визит на проверку, а не чужое лицо;
- стрижка коллеги в число клиентов не входит (пишется отдельно).

`python -m salon_analytics demo --crowded` — пример: клиенту подложен крупный кадр
с лицом Алексея, в отчёт он не попадает.

## Несколько клиентов в одном кадре

В зале 2 три кресла стоят примерно в 1.2 м друг от друга, поэтому в кадре
обычно 3+ клиента и 2+ мастера. Что для этого сделано:

- **Рассадка по всему кадру сразу** (`scene.assign_sitters`): полигоны соседних
  кресел с потолка перекрываются; венгерский алгоритм не даёт двоим сесть в одно
  кресло и одному человеку — в два.
- **«Рядом» и «руками» — разные поля** (`Tick.ring_chair`, `Tick.hands_chair`,
  `scene.resolve_staff`). Кольца 0.4–1.2 м соседних кресел перекрываются, поэтому
  время засчитывается одному креслу: тому, у чьего клиента руки мастера, а если
  руки ни у кого, то ближайшему занятому. Мастер, который красит клиента в 2-3,
  стоя ближе к 2-2, не накручивает время клиенту в 2-2.
- **Подмена ID в толпе** (`GlobalIdManager._fix_crowd_swaps`): ID близко стоящих
  людей сверяются с галереями все вместе, так что циклическая путаница A→B→C→A
  тоже исправляется (попарная проверка такое не умеет).
- **Один ID — один человек на всех камерах** (`_resolve_cross_camera`): если cam3
  и cam4 отдали один ID людям в разных креслах или дальше 1 м друг от друга,
  лишняя привязка снимается.
- **Вошли компанией одним боксом**: трек, который отделился рядом с только что
  вошедшим ID, получает свой ID со входом задним числом. Потерянный чужой ID
  он забирает только при очень похожей одежде.
- **Склейка кусков визита по убыванию сходства**, а не «кто первый попался»,
  поэтому одновременные разрывы у нескольких клиентов не перекрещиваются.
- Ночное правило «руками у двух клиентов в одну минуту» срабатывает, только если
  у каждого кресла набралось ≥ 20 с: переход к соседнему креслу — это норма.

`python -m salon_analytics demo --crowded` — день с тремя клиентами в 2-1/2-2/2-3,
двумя мастерами и компанией на диване.

## Запуск

Установка на другой компьютер (Mac / Windows) — пошагово в [INSTALL.md](INSTALL.md).

```bash
pip install -r requirements.txt pytest
python -m pytest
python -m salon_analytics markup                      # проверка разметки камер
python -m salon_analytics demo --out out --db out/salon.db
python -m salon_analytics report --ticks ticks.jsonl --persons persons.json --out out
```

`report` принимает тики глобальных ID (`Tick` из `models.py`, JSONL) — это выход
менеджера ID, по одному на человека каждые 0.5 с.

## Проверка камер на месте

Запускать на Mac mini или любом компьютере в сети салона (нужны Python 3.10+,
`ffmpeg` и зависимости из `requirements.txt`):

```bash
NVR_PASSWORD='...' python -m salon_analytics probe --nvr 192.168.1.64 --out probe
```

По каждому из 8 каналов: есть ли сигнал, разрешение, кодек, к/с, время
подключения, яркость, резкость (мутный объектив), ИК-режим, совпадает ли
разрешение с разметкой. В `probe/camN.png` — кадр с наложенной разметкой
(зелёный — кресла, синий — мойки, жёлтый — зоны, красный — маски), в
`probe/report.txt` — итог; пароль в отчёт не попадает. `--main` — основной
поток вместо суб-потока, `--source cam3=файл.mp4` — проверить на записи.

Разметка с кадров перенесена в `config/salon.yaml` (координаты нормированы 0..1,
сняты со скриншотов ±2 %). `python -m salon_analytics markup` сейчас выдаёт:

```
внимание: cam1: плохое качество кадра — почистить объектив, понизить приоритет
ОШИБКА:   cam5: камера не работает / смотрит не туда

внимание: barber-8: видно только на камерах плохого качества

внимание: вход: вход виден только с потолочной камеры зала — лица анфас не будет
```

Выводы, которые влияют на систему:

1. **Кресла 2-1, 2-2, 2-3 размечены и на cam3, и на cam4** — это ровно случай
   «одно физическое кресло на двух камерах». В реестре это одно кресло с двумя видами.
2. **Кресла на колёсах двигаются.** На cam3 полигоны 2-1 и 2-2 пустые, а кресла
   стоят в другом месте. Поэтому полигон кресла — это рабочее место, а текущее
   положение кресла берётся из детекции `chair` (`bind_moved_chairs`).
3. **cam8: полигон «??-8» уходил за кадр**, кресло реально в правом верхнем углу.
   Переразмечено как `barber-8`; валидатор ловит такие ошибки.
4. **Входная дверь видна на cam3** (стекло вверху по центру). Пока cam5 не
   работает, зона `entrance` взята оттуда, но лицо анфас с потолка не получить:
   камера у входа/кассы по-прежнему пункт №1 по железу.
5. **Ночью все 8 камер в ИК (ч/б).** Это ответ на открытый вопрос про ИК:
   ч/б кадры определяются автоматически (`is_ir_frame`), и re-ID по цвету
   одежды в них весит меньше (`reid_weight_ir`).
6. **cam1 и cam8 сильно мутные** (объектив или запотевание). Зал 1 держится на
   cam6, пока cam1 не почистят.
7. **Зеркала на cam2 и cam4, манекены-бюсты и фигурка у лестницы на cam3** —
   добавлены маски (`mirror_masks`, `ignore_masks`), плюс маска OSD.
8. **Дата на кадре в формате MM-DD-YYYY** («10-08-2026 Чт» = 8 октября).
   Это важно при подтягивании клипов из архива регистратора.
9. **Мойки:** M-1, M-2 на cam2 и M-3 в зале 2 на cam4. Бокс кресла 2-4
   перекрывает M-1 — для мойки надо смотреть на голову у раковины, а не на таз.
